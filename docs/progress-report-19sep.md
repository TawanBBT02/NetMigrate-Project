## 1. The H1 result is a specification problem, not an engine problem

Raw coverage is 83.7%, below our 85% target. But **every single unmapped line
falls into a feature family we declared out of scope** in ทก.01 §2.3.2.3:

| Family | Lines | Share |
|---|---|---|
| Credentials | 9 | 3.5% |
| STP | 6 | 2.3% |
| AAA / login | 6 | 2.3% |
| ACL | 3 | 1.2% |
| SNMP | 3 | 1.2% |
| NQA | 3 | 1.2% |
| NTP, HTTP, logging, NAT, DHCP, NBAR, OSPF-advanced, metadata | 12 | 4.6% |
| **Unclassified** | **0** | **0%** |

Excluding declared out-of-scope families, coverage is **100.0%** — the rule
engine translates every line within the command categories it claims to
support.

**Recommendation:** restate H1 in ทก.01 as two metrics rather than one:

- **H1a — in-scope coverage:** proportion of lines *within declared command
  categories* translated by rule. Target ≥ 95%. Measures the engine.
- **H1b — corpus coverage:** proportion of *all* significant lines in real
  configurations translated by rule. No target; reported as a finding.

H1b at 83.7% is then not a failure but a **result about real
configurations**: roughly one line in six of a production campus
configuration lies outside a basic VLAN/interface/routing command set. That
is a useful number for anyone scoping a migration tool, and it is the kind
of finding a single-target hypothesis would have hidden.

*Requesting advisor approval for this restatement.*

## 2. Two semantic findings — syntax translates, behaviour may not

These are the strongest material for Chapter 5, and neither was anticipated
at proposal time.

### 2.1 Static route default preference diverges

Huawei documentation: a static route with no preference configured uses
default preference **60**. Cisco's default administrative distance for a
static route is **1**.

An unqualified static route therefore translates perfectly at the syntax
level and lands with **different precedence against dynamic routing
protocols** on the target device. The system now emits a review warning once
per configuration when any static route relies on the vendor default.

This is the concrete demonstration of the syntax-acceptance vs
behavioural-equivalence limitation we recorded as a threat to validity in
§2.6.3(จ).

### 2.2 Credentials are fundamentally non-translatable

Password storage uses one-way, vendor-specific algorithms — Cisco type 5
(salted MD5), type 8 (PBKDF2-SHA256), type 9 (scrypt); Huawei
irreversible-cipher. **No transformation exists** without the plaintext,
which a saved configuration does not contain.

The system detects credential lines and emits structural manual-entry
guidance rather than attempting conversion. It also **excludes them from the
AI fallback entirely** — transmitting password hashes to a third-party API
would be a security failure regardless of usefulness.

## 3. What was built

**Engine — 11 modules, ~2,400 lines**

```
parser → vendor-neutral IR → renderer
```

Not line-by-line substitution. OSPF requires block restructuring —
`router-id` promotes onto the process line, networks regroup under area
parents, area IDs convert integer ↔ dotted-decimal — which a line-oriented
translator cannot express. Confirmed against Huawei's own configuration
examples.

**Rules:** 15 rule IDs, 5 top-level keywords, 7 interface types, both
directions. Classified D (direct, ~60%), T (transform, ~25%), S
(structural, ~15%).

**Testing — 182 tests across 7 suites**

- Unit tests per rule
- Golden-file regression (deliberately broken once to confirm the tests fail)
- Round-trip fidelity measured on the IR, not the text
- Determinism check (six conversions, byte-identical)
- Safety invariants: no AI output and no credential material outside a comment

**Tooling**

| Command | Purpose |
|---|---|
| `tools/evaluate.py` | corpus evaluation → Chapter 4 CSV |
| `tools/make_golden.py` | regenerate golden files (refuses without `--force`) |
| `tools/make_paste.py` | paste-ready configs for simulator validation |

**Documentation:** mapping specification, rule verification register,
simulator validation worksheet.
